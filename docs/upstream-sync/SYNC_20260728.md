## Why this cycle exists

Upstream shipped 10.7.3 as a **cross-tenant data leak fix**. A family of cached
`List*`/`Exec*List` endpoints reads a global cache table by `PartitionKey` and returns
the rows directly. On a cache hit `Get-Tenants` is never called, so the
`$script:CippAllowedTenantsStorage` scope that normally narrows a tenant-restricted
custom role was never applied — a restricted caller invoking one of these with
`tenantFilter=AllTenants` received **every managed tenant's data**.

Affected surfaces: users, mailbox rules, transport rules, quarantine, MFA and basic-auth
reports, conditional access policies, licenses, JIT admin, Lighthouse device compliance,
and security alerts / incidents / MDO alerts.

## Frontend delta: none

`44ac45831..d72c1e21b` touches only `package.json` and `public/version.json`. There is no
frontend code in 10.7.3 — the entire fix is backend. The frontend branch therefore carries
only the baseline bump plus this cycle's own fork work (action-menu categories).

### Protected-path adaptations

- **`Invoke-ListMailQuarantine.ps1`** is in the protected Quarantine Portal area. Only the
  AllTenants cache-read line changed (`$Messages = $Rows` gained the narrowing pipe).
  Pagination, post-filters, the 7d window and the export path are untouched. Narrowing
  happens before rows are expanded, so returned counts stay consistent.
- **`Invoke-ListLicenses.ps1`** lives at `Tenant/Reports/` in the fork but at the
  `HTTP Functions` root upstream. Applying upstream's file would have added a second copy
  and defined the function twice at module load — the same duplicate-file class of bug the
  07-27 cycle cleaned up. Ported into the fork's path instead.
- **`Invoke-ListUsers.ps1`** cannot be narrowed: the deprecated `cacheusers` blob has no
  reliable per-tenant column. A restricted caller now receives the existing deprecation
  message instead of every tenant's users; unrestricted callers keep legacy behavior.

### Module placement

Both new helpers went to `Modules/CIPPCore/Public/Authentication/`, matching upstream's
explicit warning: `$script:CippAllowedTenantsStorage` is an AsyncLocal in **CIPPCore**
module scope, so a copy living in CIPPHTTP would read that module's own permanently-empty
variable and silently filter nothing. Verified before porting:

- The fork's `Modules/CIPPCore/.../New-CippCoreRequest.ps1` defines all four storage slots
  (`CippInvocationIdStorage`, `CippAllowedTenantsStorage`, `CippAllowedGroupsStorage`,
  `CippUserRolesStorage`), so `Get-CippRequestContext` works verbatim.
- `Get-Tenants` exists only in CIPPCore and is already called from 75 CIPPHTTP endpoints,
  confirming cross-module calls resolve the slot correctly.
